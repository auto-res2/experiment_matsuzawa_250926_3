# Experimental Design
- Strategy: Experiment 1 – End-to-end HPO Efficiency on Diverse, Real Tasks
------------------------------------------------------------------
Goal: Show that CPSH delivers strictly better time-to-accuracy and GPU-hour efficiency than the de-facto standard (ASHA) and is competitive with a full surrogate method (BOHB) while keeping overhead negligible.

Setup
1. Hardware: one 8×A100 node (80 GB each); each trial uses ≤1 GPU so up to eight trials run in parallel.
2. Workloads      
   • Vision – CIFAR-10 / ResNet-18 (≈ 50 k steps, R=81 epochs).      
   • NLP – Penn-Treebank / 2-layer LSTM (R=160 epochs).      
   • Tabular – Higgs / XGBoost (R=500 boosting rounds).      
   • Large-scale bonus task – BERT-base finetuning on SST-2 with low learning-rate schedules (R=10 k steps) to test scaling.
3. Search space: learning rate, weight-decay, dropout, batch size, data-augmentation strength – identical to TUNE examples (≈ 40 dimensions with conditional branches).
4. Schedulers compared: ASHA, BOHB, CPSH (ours). Same (R, η = 3), max wall clock 12 h per benchmark, 10 random seeds.
5. Metrics:      
   a) Wall-clock hours to reach a fixed validation target (80 % / 90 % / 95 % of best known).      
   b) GPU hours consumed.      
   c) Mis-pruning rate: fraction of top-5 final configs that are ever stopped early.      
   d) CPU overhead (scheduler wall-time per decision).

Expected Results & Demonstration Power
• CPSH requires ≈30–40 % fewer GPU-hours than ASHA to reach the target on all four workloads; within 5 % of BOHB.  
• Mis-pruning ≤2 % (comparable to BOHB, far below naïve ASHA on NLP which often kills late-bloomer configs).  
• Scheduler overhead: ASHA ≈ 0.4 ms, CPSH ≈ 0.7 ms, BOHB ≈ 3–5 ms → proves “almost-free”.  
• Final test accuracy identical across methods ⇒ efficiency gain comes from smarter early stopping, not luck.

What it shows: Across heterogeneous, realistic tasks CPSH is a strict Pareto improvement over ASHA and approaches BOHB’s sample efficiency while being order-of-magnitude lighter.

Experiment 2 – Robustness to Noisy or Atypical Learning Curves
------------------------------------------------------------------
Goal: Validate that CPSH’s low-confidence projection avoids catastrophic early stopping when curves are noisy, piece-wise or have late surges.

Setup
1. Synthetic benchmark: Train a small 3-layer CNN on Fashion-MNIST but (a) randomly drop 20 % of gradient steps (simulates stragglers) and (b) inject label noise of 10 %. Create 500 random HP configs. Ground-truth final accuracy is obtained by always training to full budget R.
2. For each config record   
   • Intermediate scores every epoch.   
   • CPSH projected lower-bound ỹ after m = {2,3,4} checkpoints.
3. Run ASHA and CPSH with same Rung schedule; disable global early-stopping so every run finishes – allows post-hoc audit.

Metrics
• False-negative (mis-prune) rate: configs that end in top-K (K=1,5) but were stopped early.  
• False-positive rate: configs trained to completion but end in bottom-30 %.  
• Area under “saved-gpu” vs “lost-accuracy” curve when varying c (confidence multiplier).

Expected Results
• ASHA mis-prunes ≈8 % of top-5 configs because early noise hides their potential.  
• CPSH with default c=1 cuts this to <2 % while still terminating >35 % more poor configs.  
• Sensitivity curve flat around c∈[0.8,1.5] proving the method is not hyper-sensitive.

What it shows: The projection-plus-uncertainty explicitly guards against noisy, non-monotone curves—one of the open problems cited—confirming a key claimed strength.

Experiment 3 – Ablation & Scalability Analysis
------------------------------------------------------------------
Goal: Isolate which parts of CPSH matter and verify it scales linearly to hundreds of parallel workers.

Part A – Ablations (single node)  
Run CIFAR-10 search with:
   A1) Plain ASHA (no change).  
   A2) CPSH-NoUNC: use ŷ_R only (no σ adjustment).  
   A3) CPSH-StaticFit: fit once at m=3, never update.  
   A4) Full CPSH.
Metrics: GPU hours, mis-prune, validation accuracy.
Expected:   
• A2 saves compute but doubles mis-prune → shows uncertainty term matters.   
• A3 loses ~10 % of compute savings → shows re-fit is worthwhile.   
• Full CPSH balances both.

Part B – Multi-node Scalability (simulate on one 8×A100 via docker containers)
1. Spawn 1, 8, 32, 128 Ray workers that each run dummy training jobs lasting 5 min.
2. Measure scheduler decision throughput (decisions/sec) and CPU utilization for ASHA, CPSH, BOHB.
Expected:   
• CPSH throughput identical to ASHA (≈10 k decisions/sec) even at 128 workers; BOHB drops after 32 because GP fitting dominates CPU.  
• Memory footprint per trial: ASHA 64 B, CPSH 96 B, BOHB >20 kB.

What it shows: The tiny additional bookkeeping in CPSH does not harm horizontal scalability, validating its practical deployability in large clusters.
